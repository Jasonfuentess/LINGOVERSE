# LV-001 — Base ejecutable, identidad visual y onboarding local

**Estado:** pendiente de ejecutar con Codex

## Misión
Construir la primera base ejecutable de LingoVerse, siguiendo `docs/MASTER_PROMPT.md`. Esta tarea NO debe intentar implementar todos los motores, aventuras, audio, Supabase ni la totalidad del vertical slice. Priorizar una base mobile-first que podamos ejecutar y revisar antes de añadir contenido.

## 1. Inspección y elección tecnológica
- Inspeccionar el directorio, estado de Git, sistema operativo, Node, gestor de paquetes, SDKs y herramientas disponibles.
- Si existe código, preservarlo y explicar lo que ya hay. Si no hay aplicación, inicializar Expo + React Native + TypeScript estricto + Expo Router + React Native Web.
- Confirmar la versión efectiva de Expo y dependencias mediante documentación y/o comprobaciones. Expo SDK 58 fue publicado el 15/10/2026; Expo SDK 57 puede ser una base pragmática si el soporte real de herramientas y NativeWind es mejor. No asumir compatibilidad por el número de versión.
- NativeWind: verificar primero; si no hay integración estable probada con el SDK escogido, usar `StyleSheet` y tokens de diseño TypeScript. No instalar versiones prerelease solo por preferencia estética.
- No instalar servicios o componentes que todavía no vamos a utilizar.

## 2. Estructura de carpetas
Proponer e implementar una estructura ligera y extensible para `app/`, `src/components/`, `src/theme/`, `src/features/`, `src/domain/`, `src/storage/`, `src/content/` y `docs/`. Ajustar si Expo requiere otra convención; documentar decisiones. La lógica de dominio no debe depender de React Native.

## 3. Diseño visual original
- Crear tokens de color, tipografía, espacios, radios y superficies, con diseño cuidado y original; no copiar Duolingo ni usar estética infantil.
- Priorizar accesibilidad, contraste, áreas táctiles y pantallas pequeñas.
- Desarrollar un inicio funcional que muestre preferencias reales del usuario y siguiente acción disponible. No presentar progreso ficticio ni retos inexistentes como completados.
- No crear cinco tabs vacías para aparentar que todas las secciones están listas; incluir navegación hacia secciones solo cuando haya una experiencia útil o un estado informativo claramente identificado como pendiente.

## 4. Onboarding funcional y modo invitado
- Permitir iniciar como invitado sin cuenta.
- Elegir idioma a aprender (`en` o `fr`) y región del entrenador (`es-SV`, `es-MX`, `es-CO`, `es-AR`).
- Separar tipadamente `learningLanguage`, `interfaceLanguage`, `coachLocale` y `voiceProvider` como exige el documento maestro.
- Guardar y restaurar preferencias tras cerrar y abrir la app, tanto en web como en nativo (cuando se pueda verificar).
- En Perfil permitir consultar y cambiar la selección de idioma y entrenador.
- Mantener Roast Me/descripciones con groserías desactivados por defecto; no introducir consentimiento adulto hasta implementar un flujo completo y explícito.

## 5. Persistencia local
- Diseñar una interfaz tipada de almacenamiento/repositorio desacoplada de las pantallas.
- Para nativo, utilizar la solución compatible oficial de Expo (p. ej. `expo-sqlite`/kv-store si está verificada); para web, un adaptador basado en almacenamiento local del navegador de manera segura, sin asumir disponibilidad de APIs durante render en servidor.
- Considerar versionado básico de preferencias y migraciones posteriores, sin sobreingeniería.
- Sin cuentas, Supabase, sincronización ficticia ni llamadas externas.

## 6. Validación y documentación
- Incluir scripts de typecheck, lint y pruebas automatizadas reproducibles.
- Agregar pruebas de defaults de preferencias, serialización/persistencia y cambios de idioma/entrenador como mínimo; separar las pruebas que requieren plataforma real.
- Intentar ejecutar y verificar la aplicación web en el entorno disponible. Verificar Android/iOS solamente si existe infraestructura real; no declarar compatibilidad probada donde no se pudo ejecutar.
- Crear/actualizar `README.md`, `docs/ARCHITECTURE.md`, `docs/DESIGN_SYSTEM.md` y `docs/PROJECT_STATE.md` con alcance real de LV-001.
- Finalizar con informe compacto: qué se construyó, archivos, versiones instaladas, comandos y resultados, bloqueos, capturas si es posible y propuesta de siguiente tarea LV-002 (sin implementarla).

## Restricciones
- Presupuesto infra inicial: USD 0; no suscripciones, APIs comerciales ni publicaciones.
- No crear backend .NET.
- No desarrollar todavía contenido A1 extenso, Variety Engine, Humor Engine, Dialogue Engine, Voice Engine completo o tareas posteriores.
- No usar `Math.random()` para fingir variedad o resultados.
- No hacer `git push`, desplegar ni publicar.
- Evitar borrar cambios preexistentes del usuario.

## Criterios de aceptación
LV-001 estará terminada solo cuando: la aplicación compile; el onboarding permita escoger inglés/francés y una de las cuatro regiones; las opciones se restauren al reiniciar; Inicio y Perfil muestren el estado auténtico; typecheck/lint/tests disponibles pasen; exista documentación de comandos de arranque y limitaciones verificadas. Si algo falla o no se probó, declararlo explícitamente como pendiente.

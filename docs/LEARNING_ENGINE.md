# Learning Engine · LV-002

Motor TypeScript puro en `src/domain/learning/`, sin React, almacenamiento, reloj, red ni aleatoriedad. Contratos en `models.ts`: Lesson, LessonVariant, Exercise (choice/text), LearnerAnswer, Evaluation, LearningEvent y MissionProgress. La UI consume estos contratos y no decide qué respuesta es correcta ni cómo se avanza.

`validateLesson(unknown)` comprueba esquema v1, textos, IDs, tipos de ejercicio, objetivos, opciones válidas, destinos, unicidad y alcanzabilidad. Recorre todas las rutas correctas: deben terminar, sin ciclos, con todos los objetivos en el mismo orden. Esto valida estructura y progresión editorial, no certifica una revisión pedagógica externa.

`beginMission(lesson, run, selector?)` inicia un recorrido sin modificar la lección. El selector inyectable recibe la lección y el número de recorrido y devuelve un ID de variante válido. El predeterminado alterna variantes por módulo; no es el Variety Engine ponderado. La variante permanece fija durante el recorrido y se persiste. No hay `Math.random()` ni promesa de contenido infinito.

`evaluateAnswer(exercise, answer)` evalúa exclusivamente contenido editorial. Selección mediante ID de opción; texto mediante lista explícita de expresiones aceptadas. Normalización: Unicode NFC, minúsculas francesas, apóstrofo recto/curvo, espacios y puntuación. Conserva los acentos: `ca coute` no equivale a `ça coûte`. No hace corrección semántica arbitraria, reconocimiento de voz ni análisis fonético. Una frase correcta que no esté en las alternativas conocidas puede rechazarse; la ayuda indica exactamente las expresiones admitidas.

`submitAnswer` registra la respuesta y devuelve feedback. Un error conserva escena/objetivos y explica cómo corregirlo. Un acierto queda pendiente de `continueMission` para poder leer la intervención del personaje; no permite enviar otro acierto para saltarse una escena. Continuar confirma un objetivo y aplica la rama. Solo continuar tras la última despedida produce estado completed. No hay XP ni niveles globales inferidos.

`restoreProgress` reproduce los eventos y compara todos los campos calculados con el documento almacenado: detecta estados incompatibles o incoherentes, escenas fuera de orden y finalizaciones sin recorrido. Es integridad lógica local, no protección criptográfica contra edición deliberada de eventos válidos. Límite de 1024 eventos antes de una respuesta nueva (el último continuar puede llevar a 1025), texto máximo 400 caracteres y registro máximo 500000 caracteres. Al agotar intentos se conserva el avance y se permite reiniciar.

`MissionRepository` reutiliza KeyValueStorage y los adaptadores de LV-001. Clave independiente: `lingoverse.mission.fr-a1-paris-cafe.v1`. No toca `lingoverse.preferences.v1`. No sustituye datos dañados sin confirmación del usuario. No existen migraciones anteriores de misión; versiones no admitidas se muestran como error y permiten reinicio explícito.

El proveedor compartido guarda antes de actualizar la UI y bloquea acciones simultáneas. Persiste también el feedback; salir o recargar no obliga a repetir una respuesta ya aceptada. Los errores de lectura ofrecen reintento/reinicio y los de escritura conservan el estado anterior. Reiniciar reemplaza el último recorrido y sus errores; no se presenta un historial acumulado que no exista.

Cada instancia del repositorio debe leer antes de escribir. Guarda una instantánea del registro leído y la compara antes de reemplazarlo; si otra ventana guardó un cambio, lanza MissionConflictError y la UI ofrece releer. Las escrituras se serializan en el mismo runtime; el adaptador web usa además Web Locks cuando está disponible para coordinar pestañas del mismo origen. Sin Web Locks, se detectan escritores desactualizados secuenciales, pero no se garantiza atomicidad entre procesos/pestañas que escriban exactamente a la vez. El adaptador nativo actual se usa desde un único runtime. La coordinación de pestañas no se validó en navegador real; sí los conflictos/serialización entre repositorios en pruebas unitarias.

Para añadir contenido: mantener IDs, agregar escenas/alternativas en el paquete y ejecutar el validador y las pruebas de rutas. Cambiar el significado de un ID exige una versión/migración explícita antes de reutilizar progreso anterior. Otros idiomas, tipos de ejercicio, paquetes descargables y progresión espaciada quedan fuera de esta entrega.
